# 🚀 Project Title: End-to-End Observability Pipeline
**Objective:** Deploy a sample microservices application and implement a complete monitoring, logging, and alerting system to ensure system reliability.

## 📅 Weekly Breakdown

### Week 1: Foundations of Observability
**Goal:** Understand *why* we monitor and the difference between the "Three Pillars of Observability."
*   **Concepts:** 
    *   Monitoring vs. Observability.
    *   The Three Pillars: **Metrics** (numbers), **Logs** (events), and **Traces** (requests).
    *   Introduction to SLIs (Service Level Indicators) and SLOs (Service Level Objectives).
*   **Hands-on:** 
    *   Set up a local development environment (Ubuntu/WSL2).
    *   Install Docker and Docker Compose.
*   **Deliverable:** A short document defining the SLIs/SLOs for a hypothetical e-commerce app.

### Week 2: Infrastructure & Application Setup
**Goal:** Get a "target" application running that we can actually monitor.
*   **Concepts:** 
    *   Containerization basics.
    *   How applications expose health checks (`/health` or `/metrics` endpoints).
*   **Hands-on:** 
    *   Deploy a sample multi-tier application (e.g., a Python Flask app with a Redis database) using Docker Compose.
    *   Simulate "traffic" using a tool like Apache Benchmark (`ab`) or Locust.
*   **Deliverable:** A running containerized application.

### Week 3: Metrics Collection with Prometheus
**Goal:** Implement the "Metrics" pillar.
*   **Concepts:** 
    *   Pull vs. Push mechanisms.
    *   Time Series Databases (TSDB).
    *   PromQL (Prometheus Query Language).
*   **Hands-on:** 
    *   Install and configure **Prometheus**.
    *   Set up **Node Exporter** (for hardware metrics) and **cAdvisor** (for container metrics).
    *   Configure Prometheus to scrape metrics from the sample app.
*   **Deliverable:** A working Prometheus instance showing raw metric data.

### Week 4: Visualization with Grafana
**Goal:** Turn raw numbers into actionable insights.
*   **Concepts:** 
    *   Data sources and Dashboards.
    *   Visualizing trends (Graphs, Gauges, Heatmaps).
*   **Hands-on:** 
    *   Install **Grafana** and connect it to Prometheus.
    *   Build a "System Health Dashboard" (CPU, RAM, Network).
    *   Build an "Application Dashboard" (Request rate, Error rate, Latency).
*   **Deliverable:** A professional-looking Grafana dashboard.

### Week 5: Log Management (The ELK/PLG Stack)
**Goal:** Implement the "Logs" pillar to debug *why* something failed.
*   **Concepts:** 
    *   Structured vs. Unstructured logging.
    *   Log aggregation and indexing.
*   **Hands-on:** 
    *   Deploy **Loki** (for logs) and **Promtail** (for shipping logs). 
    *   *Alternative:* Use the ELK stack (Elasticsearch, Logstash, Kibana).
    *   Create a dashboard in Grafana that correlates a metric spike (from Week 4) with a specific error log.
*   **Deliverable:** A centralized logging system where logs are searchable by labels.

### Week 6: Alerting, Chaos, and Final Presentation
**Goal:** Close the loop by automating notifications and testing the system.
*   **Concepts:** 
    *   Alerting rules and thresholds.
    *   Notification channels (Slack, Email, PagerDuty).
*   **Hands-on:** 
    *   Configure **Prometheus Alertmanager**.
    *   **Chaos Testing:** Intentionally crash a container or spike the CPU to trigger an alert.
    *   Verify that the alert reaches the notification channel.
*   **Deliverable:** A final project demo showing a failure $\rightarrow$ alert $\rightarrow$ log analysis $\rightarrow$ resolution.

## 🛠️ Recommended Tech Stack
*   **Runtime:** Docker & Docker Compose
*   **Metrics:** Prometheus
*   **Visualization:** Grafana
*   **Logging:** Grafana Loki / Promtail (Lighter for students than ELK)
*   **App:** Any simple Python/Node.js app with a Prometheus client library.

## 🎓 Learning Outcomes
By the end of this project, students will be able to:
1.  Distinguish between metrics and logs.
2.  Deploy and configure a production-grade monitoring stack.
3.  Write queries to analyze system performance.
4.  Set up automated alerting to reduce Mean Time to Recovery (MTTR).
